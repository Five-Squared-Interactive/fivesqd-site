# Build on it

Everything that opens, moves or syncs a world is open source under MIT,
and the
format is a written specification with a conformance suite.

## Make worlds

You have a scene and someone to show it to. Install the Blender add-on,
press Save and Publish, send the link. Then add `/index.veml` to the
address and see how little the world is; it is text you can read.
[Your first world](/first-world)

## Put your own things in a world

You have models, data, a game, a simulation. A world's document can load
your glTF, script behaviour in JavaScript inside WebVerse's sandbox, and
link to anything at a URL. A world with shared state of its own, things
people place that stay placed or a world fed by other systems, can run on
WorldOS, with plugins that talk to the systems you already have.

## Build the pieces yourself

You want a different page to open worlds, a different editor, a host, a
sync service, a connector. The format is open, WebVerse and the engine are
open, the sync
layer is open and standalone, and a world at your own address names
nothing of ours. Build what fits and it works with everything else.

## Where to start

- The format: VEML, a written specification with a conformance suite,
  [on GitHub](https://github.com/Five-Squared-Interactive/VEML).
  *(Founder, 2026-11-13: the current spec goes on GitHub; the site never
  says "the earlier documents are on GitHub".)*
- The page that opens worlds: WebVerse, and StraightFour under it.
- Being together: WorldSync, designed so an engine you already use can
  adopt it.
- A world with shared state of its own: WorldOS.
- The code: [github.com/Five-Squared-Interactive](https://github.com/Five-Squared-Interactive).
